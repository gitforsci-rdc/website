Add your file with a pull request

Your part after the workshop of 20 November 2026. About 30 minutes

In the workshop you watched a file go into the shared repository. This page has the same steps for you, to do at home. You bring the file with your three lines into the shared repository workshop, on a branch of your own and through a pull request. Lars reads it, asks one question and merges it.

Open your pull request by Friday 4 December 2026. Lars reviews the pull requests that are open by that date.

Steps 1 to 5 open the pull request. Step 6 is the review: a question from Lars, your answer as a commit, and the merge.

Before you start

You need the finished pre-work:

  • the repository workshop, cloned in Step 5 to Documents/gitrepos/workshop
  • your own repository teaching-your-username with the file your-username.md, cloned in Step 6 to Documents/gitrepos/teaching-your-username

Is something missing? Go through Step 5 and Step 6 of the pre-work first.

Step 1: open the shared repository

You cloned workshop in Step 5. Do not clone it again.

  1. Open GitHub Desktop. Click Current Repository at the top left and choose workshop.
  2. Click Fetch origin at the top. If the button then reads Pull origin, click it once more. Your copy now has the latest state of main.

Step 2: create a branch

A branch is a line of work of your own in the shared repository. You can add files on it without touching main.

  1. Click Current Branch at the top, then New Branch.
  2. As the name, write people- followed by your GitHub username, for example people-octocat. Click Create Branch.
  3. The top now reads Current Branch: people-your-username.

Step 3: copy your file

You copy the one file with your three lines from your own repository into the shared one. Your own repository stays as it is.

Copy the file, never the whole folder teaching-your-username. The folder carries a hidden folder named .git, and Git would then see a repository inside a repository.

  • macOS
  • Windows
  1. In Finder, open Documents/gitrepos/teaching-your-username.
  2. Click the file your-username.md once and press Command and C.
  3. Open Documents/gitrepos/workshop/people and press Command and V.
  1. In Explorer, open Documents\gitrepos\teaching-your-username.
  2. Click the file your-username.md once and press Ctrl and C.
  3. Open Documents\gitrepos\workshop\people and press Ctrl and V.

The folder people now holds _example.md and your file.

Step 4: commit

  1. Go back to GitHub Desktop. The tab Changes lists people/your-username.md with a tick.
  2. Write a message in the field Summary at the bottom left, for example Add my teaching context.
  3. The button below now reads Commit 1 file to people-your-username. If it ends in to main, you are on the wrong branch. Go back to step 2.
  4. Click the button.

Step 5: publish the branch and open the pull request

Your branch exists only on your laptop so far.

  1. Click Publish branch at the top. GitHub Desktop pushes the branch with your commit to GitHub.
  2. Click the blue button Preview Pull Request. A window shows your file.
  3. At the top it reads base: main and compare: people-your-username. That is how it should be. Click Create Pull Request at the bottom right. Your browser opens on github.com.
  4. The text field holds a template with two lines. Fill in File with people/your-username.md.
  5. On the right, click Reviewers and type larnsce. Choose the name from the list.
  6. Click the green button Create pull request.

Your pull request is open. Do not merge it yourself, also when GitHub shows you the button. Reading by a second person is the point of the exercise.

Step 6: review, answer, merge

You are the author of the pull request, Lars is the reviewer.

  1. Lars: writes one question on a line of your file. GitHub sends you a notification by email.
  2. You: open your pull request in the list of pull requests. You see the comment there. Answer it in the file: open Documents/gitrepos/workshop/people/your-username.md in your editor, change the line and save. In GitHub Desktop, write a commit message, click Commit 1 file to people-your-username, then Push origin. The open pull request shows the new commit. You need no second pull request.
  3. Lars: reads your commit and merges the pull request.
  4. You: in GitHub Desktop, click Current Branch and choose main. Click Fetch origin, then Pull origin. The folder people on your laptop now holds the files of everyone who is merged.

Done when

Your pull request stands under closed pull requests with the purple mark Merged, and your file is in the folder people on main.

Stuck?

  • A commit on main instead of your branch. As long as you have not pushed, GitHub Desktop shows the button Undo at the bottom left, below the commit. Click it. Then create the branch (step 2). GitHub Desktop asks whether your changes should come along. Choose to bring them to the new branch.
  • Nothing appears in the tab Changes. The file is in a different place. It belongs into gitrepos/workshop/people.
  • Changes shows a folder instead of one file. You copied the repository folder. Delete the copied folder from workshop/people and copy only the file your-username.md.
  • The push is rejected. Your commit carries your real email address, and your account blocks such pushes. In GitHub Desktop, open Settings (Windows: File, Options), Git, tab Author, choose the address that ends in @users.noreply.github.com and click Save. Then click Undo at the bottom of the tab Changes and commit again.
  • Publish branch is missing, the top reads Push origin. The branch is published already. Click Push origin if commits are missing and go on with step 5.
  • The name is not in the list of reviewers. Go on without a reviewer. Lars sees every new pull request in the repository.
  • Anything else: write a comment in your issue in the workshop repository.
